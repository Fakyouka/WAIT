# Камера и изображение WAIT

Система рассчитана на Godot 4.7.2 и существующий Compatibility renderer.
Запускайте `scenes/main/main.tscn` (текущая главная сцена).

## Inspector

В `main.tscn` выберите **Main → PixelPostProcess**:

| Параметр | Начальное значение | Назначение |
| --- | --- | --- |
| `enabled` | `true` | Низкое разрешение и все эффекты изображения. При выключении — нативное разрешение области изображения и обход обработки. |
| `virtual_resolution` | `640 × 360` | Реальный размер 3D render target; также задаёт соотношение сторон. |
| `integer_scaling` | `true` | Целочисленный масштаб с полями для одинакового размера каждого пикселя. |
| `color_levels` | `64` | Уровни на канал, включая чёрный и белый. |
| `dithering_strength` | `0.25` | Сила Bayer 4×4 относительно одного шага палитры; `0` отключает dithering. |
| `grain_strength` | `0.001` | Общий диапазон статичного монохромного шума: ±0.0005; `0` отключает шум. |
| `vignette_strength` | `0.08` | Слабое затемнение краёв; `0` отключает виньетку. |
| `vignette_radius` | `0.65` | Начало затемнения: расстояние 0 в центре, 1 в углах. |
| `vignette_softness` | `0.4` | Ширина плавного перехода виньетки. |

В `player.tscn` выберите **Player → Head → CameraEffects**:

| Параметр | Начальное значение |
| --- | --- |
| `enabled` | `true`; выключение возвращает исходный transform |
| `breathing_enabled` | `true` |
| `breathing_amplitude` | `0.0015 м` (1.5 мм) |
| `breathing_speed` | `0.2 Гц` (цикл 5 секунд) |
| `sway_enabled` | `true` |
| `sway_strength` | `0.08` |
| `sway_smoothing` | `0.075 с`, время экспоненциального затухания |
| `sway_max_angle` | `0.35°` на ось |
| `micro_movement_enabled` | `true` |
| `micro_movement_strength` | `0.0007 м` (0.7 мм) |
| `micro_rotation_strength` | `0.025°` |
| `micro_movement_speed` | `0.11 Гц` |
| `tilt_enabled` | `true` |
| `tilt_strength` | `1°`, максимальный наклон по Z |
| `tilt_smoothing` | `0.12 с` |
| `tilt_speed_threshold` | `25°/с`; ниже этой скорости наклон стремится к нулю |

При активном повороте дыхание плавно ослабевает. Micro movement использует
медленные синусы без случайных скачков; sway и tilt затухают после остановки.
Параметры можно проверять во время запуска через вкладку **Remote**; такие
изменения не сохраняются в сцене. Для постоянной настройки используйте **Local**.

## Устройство и дальнейшее развитие

```text
Main
├── WorldViewport (SubViewport)
│   ├── WorldEnvironment
│   ├── DirectionalLight3D
│   ├── Player → Head → CameraEffects → Camera3D → RightHandAnchor
│   └── Location
├── PixelPostProcess (CanvasLayer, layer -1)
│   ├── Background
│   └── Image (TextureRect, nearest)
└── UI (CanvasLayer, layer 1)
```

Единственная 3D-камера находится в `WorldViewport`. Он использует общий World3D,
чтобы геометрия оставалась видимой в редакторе; у корневого viewport нет камеры,
поэтому повторного рендера мира нет. Освещение, туман и Environment остаются
в существующем ресурсе `resources/environments/wait_overcast_evening.tres`.

Один canvas shader получает ViewportTexture, читает центры texel и объединяет
quantization, Bayer dithering, статичный pixel grain и vignette. Все эффекты
привязаны к пикселям внутреннего изображения. Нет screen-texture копирования,
анимации шума или дополнительных 3D-камер. Nearest установлен на `Image`;
материалы моделей и их текстуры сохранены.

HUD, подсказки и меню добавляйте в **Main/UI**, вне `WorldViewport`: они рисуются
после постобработки в полном разрешении окна. Существующий `canvas_items` stretch
может масштабировать координаты UI, но UI не рендерится в 640×360.

`PixelPostProcess` передаёт только необработанный корневым UI ввод в `WorldViewport`
и переводит координаты указателя в его пространство. Player использует
`screen_relative`, поэтому чувствительность не зависит от внутреннего разрешения.
Для будущего взаимодействия взглядом используйте реальную `player.camera`
и центр **её viewport**, учитывая визуальный offset. Логические повороты Player/Head
применяются сразу, с прежними пределами и кривой мыши; перемещения игрока нет.

## Размер окна и ограничения

Изображение сохраняет пропорции виртуального разрешения и центрируется с полями.
При включённом `integer_scaling`, например, 1366×768 показывает 1280×720 с полями
43 пикселя по бокам и 24 сверху/снизу. При отключении изображение занимает
максимальную вписанную область, но при дробном масштабе ширина отдельных пикселей
может различаться. В окнах меньше виртуального разрешения применяется nearest
уменьшение с сохранением пропорций: часть исходных пикселей неизбежно пропускается.

Постобработка видна при запуске главной сцены; обычное 3D-окно редактора остаётся
без фильтра. Запуск `player.tscn` отдельно проверяет движения камеры, но не
постобработку, которая подключена в главной сцене.

## Проверка

- Headless import/load: `godot --headless --editor --path . --quit`.
- Запуск главной сцены: `godot --path .` или F5 в редакторе.
- Мышь поворачивает камеру, Escape освобождает/захватывает указатель.
- Проверены Compatibility/OpenGL, сохранность FOV и предмета в руке, ограничения
  взгляда, неподвижная позиция игрока, отключение эффектов и изменение параметров.
- Временная проверка с реальным рендером подтвердила 640×360, отсутствие второй
  камеры, одинаковые блоки 2×2 при 1280×720 и идентичные статичные кадры при
  выключенных движениях камеры. Проверены окна 480×270, 1000×1000, 1280×720,
  1366×768 и 1600×720.

При запуске CLI в ограниченной среде возможны сообщения о недоступности системного
хранилища сертификатов, записи глобальных настроек Steam-редактора или кэша GLSL.
Это ограничения окружения, а не parser/shader errors; обычный запуск из открытого
редактора проверен отдельно.
